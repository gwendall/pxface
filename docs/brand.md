# PXFACE brand system

PXFACE is the product, studio, renderer, API, and type family name. The core
idea is concise: pixel type you can shape, export, install, and automate.

## Positioning

- Name: **PXFACE**
- Descriptor: **3×5 pixel type studio**
- Signature: **Pixel type, made tangible.**
- Canonical domain: `pxface.com`
- Type family: **PXFACE 3×5**
- Developer surfaces: the `pxface` package, **PXFACE Render API**, and
  `pxface-render` agent skill

Use PXFACE as one word in uppercase. Use `pxface` for package names, event
names, paths, and other machine identifiers. Do not abbreviate the public brand
to PX alone.

## Visual language

The brand is a functional pixel workshop: sharp edges, dense controls, visible
grid logic, high contrast, and one signal color. It should feel designed for
working typographers rather than styled like a game or nostalgic emulator.

- Primary dark: `#191917`
- Primary light: `#F1F0E9`
- Signal orange: `#FF4E1A` in artwork, `#E94316` in the light UI
- Interface sans: Geist
- Interface mono: Geist Mono
- Display face: PXFACE 3×5
- Shape rule: square corners and crisp edges

The PX pixel mark remains the compact icon. In the horizontal signature, the
orange mark supplies the letters PX and the light pixel lettering supplies
FACE, so the complete lockup reads PXFACE once. Never place the PX mark beside
a second full PXFACE wordmark.

## Voice

Use short, concrete language. Describe the output or action directly: “Copy for
Figma”, “Editable SVG”, “Download font”. Avoid retro-game language, inflated
creative claims, and jokes that obscure the tool.

## Migration contract

PXFACE launched as version 2.0.0 of the font and renderer identity. The former
PXWORD domain, download paths, response headers, and SVG renderer attribute are
temporary compatibility aliases. New documentation and integrations must use
PXFACE names only.
